### 环境与验证经验（重要）
- 本机无法构建：`dotnet`(SDK 10) 跑 NuGet 还原时 `NuGet.Configuration.ConfigurationDefaults` 静态构造抛 `Value cannot be null (Parameter 'path1')`（最小空白项目也复现），属环境问题；`msbuild` 被安全策略拦截，无法调用。
- 因此改用静态校验：
  - 所有 XAML 可被 XML 解析（`Resources/Custom.xaml` 是运行时模板，非编译项，天然不可单独解析）。
  - `Handles X.Y` 的目标名均存在：需同时统计 `x:Name` 与 `Name` 属性。
  - 代码/XAML 中引用的 `Settings` 键均在 `Settings.vb` 的 Entries 中定义。
- **Edit/Write 工具会改写行尾符**（.vb/.xaml 原本 LF，写成 CRLF；个别文件相反）。改完务必用脚本按 HEAD 版本恢复 EOL，否则 diff 会变成整文件重写。
- MeloongCore 子模块原为空；用 `git -c http.schannelCheckRevoke=false -c http.sslVerify=false` 才能克隆（schannel 吊销检查失败），随后需 checkout 到 superproject 记录的 commit 以保持 gitlink 干净。

### 构建验证结论（关键，避免下次重复踩坑）
- 用 dotnet SDK 10 构建本项目**必然失败**：只生成 `obj/**/*.g.i.vb` 而不生成 `*.g.vb`，导致所有 XAML 分部类缺 Inherits 与 WithEvents 字段，报 500+ 个 BC30506/BC30590。
- 已用 `git stash` 在未修改的 HEAD 基线上复测：基线也报 523 个错误（修改后 502 个），证明是工具链问题而非代码问题。
- VS 自带的构建工具路径被安全策略拦截，无法调用。
- 副作用：该构建会清掉 `obj/Debug` 里原有的 exe 和 `*.g.vb`（均在 gitignore 内，用 VS 重新生成即可）。
- 结论：本项目只能靠静态校验（XAML 可解析 / Handles 目标存在 / Settings 键都有定义）兜底。
